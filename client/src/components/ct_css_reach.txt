# THE REACHABILITY REGISTER — which of the port's selectors can match, and
# which are emitted knowing nothing will.
#
# ── WHY THIS FILE EXISTS ──────────────────────────────────────────────────
#
# `ct_components_css.nim` compiles the vendored CodeTracer stylesheets into
# the CSS this site serves. `Dropped` in that module records the rules the port
# does not emit, each with a reason, and a test asserts every dropped rule is
# dropped on purpose. THE CONVERSE HAD NO CHECK AT ALL: nothing asserted that a
# rule which was NOT dropped can actually match something. A rule could be
# vendored, transpiled, scoped, served and matched by nothing, and the only
# evidence either way was that somebody had once looked.
#
# Three defects came out of that gap, all measured:
#
#   1. `.component-container`, CodeTracer's panel surface, was vendored and
#      served while `grep -c component-container` over `components/debugger.nim`
#      and `pages/debug.nim` was 0. It was reported to the owner as "ported".
#      It is live now — five pane bodies wear it — and it is the first LIVE row
#      below, which is what keeps it live.
#
#   2. The nine vendored CodeTracer icons were published and their `url()`s
#      fixed from 404s to 200s, and a rendered probe then proved that all nine
#      rules work when correct markup is injected AND that zero of the nine
#      selectors are emitted anywhere — over 349 built pages and all three JS
#      bundles, raw and char-code-decoded. The urls resolve. Nothing reaches
#      them. See `INERT class ct-origin-*` and the two rows after it.
#
#   3. `.separate-bar` and `.dropdown-list` were each given a colour binding
#      and both match zero elements.
#
# ── WHAT A ROW MEANS ──────────────────────────────────────────────────────
#
#   LIVE  <kind> <pattern>      this site's markup emits it, and the gate
#                               PROVES that against the built tree. A row here
#                               is a claim of liveness that something checks.
#
#   INERT <kind> <pattern>      the port emits it knowing nothing matches it.
#                               The reason has to say WHAT WOULD HAVE TO EXIST
#                               for it to come back, because that is the
#                               sentence the three defects above were missing.
#
# `<kind>` is one of:
#
#   class       a `.foo` in a port selector.
#   classpart   the substring in a `[class*="foo"]`, which matches a class
#               attribute containing it anywhere.
#   id          a `#foo`.
#   element     a bare tag name, in a selector that names no class, id or
#               classpart at all.
#
# `<pattern>` may use `*` as a wildcard. EXACTLY ONE row must cover each item
# the port emits — not "at least one" — so a reader looking for why a class is
# inert finds one answer, and so two families cannot quietly overlap.
#
# The reason is the indented block under the row. It is required and it is not
# decoration: `Dropped`'s precedent is that the reason is the whole value of
# the entry.
#
# ── WHY THIS IS A DATA FILE AND NOT A `seq` IN THE NIM MODULE ─────────────
#
# Because TWO checks in two languages have to read the same rows, and a second
# copy of the register is the divergence this whole module exists to prevent:
#
#   * `client/tests/test_ct_components_css.nim` `staticRead`s it and asserts
#     the PARTITION IS TOTAL — every class, classpart, id and element the port
#     emits is covered by exactly one row, and every row covers something. It
#     needs no markup and no build, so it runs in seconds and a re-vendor that
#     introduces an unclassified selector fails there first.
#
#   * `tools/ci/check-css-reachable.mjs` parses it and asserts the rows are
#     TRUE OF THE MARKUP — every LIVE row is emitted by the built tree, and no
#     INERT row is. It needs the exported site, so it runs in the `debug-route`
#     job via `ci/test/ct-css-reachable.sh`.
#
# Neither half is the gate on its own. The first says the register accounts for
# everything the port emits; the second says the register is not lying. The
# claim the three defects needed is their composition.
#
# ── WHAT "EMITTED BY THE MARKUP" MEANS, AND WHAT IT DELIBERATELY DOES NOT ──
#
# Two sources count, and both are syntactically class values:
#
#   * a token of a `class="…"` attribute in one of the ~348 pages
#     `cd client && just export-hydrated` produces;
#   * a token of a `class = "…"` literal, or a `classList.add/remove/toggle`
#     argument, in a `.nim` file under `client/` — which is what covers a class
#     the renderer writes on a branch the demo corpus never takes.
#
# A THIRD SOURCE IS MEASURED AND DELIBERATELY NOT COUNTED. The gate also reads
# every shipped JS bundle, decoding the char-code arrays Nim-JS emits some
# string literals as, and the decoder is validated on two literals known to be
# present (`copyable`, which `hydrate.js` carries ONLY encoded, and
# `identifier`, which it carries both ways) so that a null from it is a
# measurement rather than a failed grep. It is not counted as liveness because
# a JS string literal is not a class value, and the measurement says exactly
# what that would have cost: `active`, `checkbox`, `hidden`, `open` and
# `selector` are all port classes AND all present as ordinary words in
# `hydrate.js`, and not one of them is a class this site writes. Promoting a
# bundle token to "matched" would have excused SIX ROWS, which the gate prints
# on every run: `active`, `checkbox`, `hidden`, `open`, `selector` and the SVG
# element `line`. `hidden` and `active` sit in the same family as
# `.dropdown-list`, which is defect 3.
#
# So the bundle is a cross-check on the Nim scan, not a source of excuses. A
# row may name `bundle` as its evidence (`LIVE class <name> bundle`) when a
# class genuinely only exists in SDK code compiled into the bundle and in no
# `client/` source; no row does today, and such a row has to argue for itself.
#
# ── WHAT IS OUT OF SCOPE, AND WHY ─────────────────────────────────────────
#
#   * PSEUDO-CLASSES AND PSEUDO-ELEMENTS are not inventory items. `:hover`,
#     `:focus-visible`, `:disabled`, `:target`, `:nth-child()` and
#     `::placeholder` are STATE, not identity, and cannot be found in static
#     markup. A rule on `X:hover` is therefore an item for `X` alone — which is
#     the honest reading and NOT a hole the three defects fit through:
#     `.ct-origin-icon-sigma .ct-origin-badge-icon` is a DESCENDANT selector,
#     so it is two class items, and both are below as INERT.
#
#   * A CLASS INSIDE `:not()` IS NOT AN ITEM, because the rule matches when it
#     is ABSENT. Classes inside `:has()`, `:is()` and `:where()` ARE items, for
#     the opposite reason — and the nesting of the two decides, not the
#     innermost pseudo. The worked example is upstream's one use of
#     `#isonim-debug-controls`, which occurs ONLY as
#     `:not(:where(#isonim-debug-controls *))` on the image-button rule: the
#     rule applies to every image button that is NOT inside the caption bar's
#     debug-controls toolbar, so that id is not something this site has to
#     emit, and the register carries no row for it. A text scan of the built
#     stylesheet reports it as an id the port names; the inventory does not,
#     and the inventory is right.
#
#   * NON-`class` ATTRIBUTE SELECTORS are not items: `[data-selected="true"]`,
#     `[data-disabled="true"]`, `[data-focused="true"]`, `[data-focus-mode]`,
#     `[data-tippy-root]`, `[data-placement^=…]` and `[style*=…]`. The first
#     four are state. `[data-tippy-root]` is identity, and it is honest to say
#     so: it is not checked here, and it is the only one that is not state.
#     Every rule that names it also names `.tippy-box` or `.tippy-content`,
#     which are items and are INERT, so the family is accounted for.
#
#   * `[data-register="debugger"]` is on `<html>` and prefixes EVERY port
#     selector. Matching is about the class, never about the register, so it is
#     skipped by the same rule as every other non-`class` attribute.
#
#   * A DECLARATION the browser discards is NOT in scope, and that is a known
#     gap with a live instance: `.dropdown-list` carries `z-index: 50 + 7`,
#     which the transpiler passes through unevaluated and the browser throws
#     away (confirmed against a control: inline `z-index: 57` computes to 57,
#     `50 + 7` computes to `auto`). It is the same class of silence one level
#     down — a rule that matches, carrying a declaration that does nothing —
#     and nothing in this repository catches it. `ct_styl` raises on an
#     unsupported at-rule or mixin and passes arithmetic through silently.
#

INERT class ct-origin-*
    DEFECT 2 — THE NINE VENDORED ICONS, AND THE ROW IS A CORRECTION OF THE
    RECORD AS WELL AS A CLASSIFICATION.
    `button.styl` draws a value's ORIGIN as a badge: `.ct-origin-badge` with
    an `.ct-origin-badge-icon` and an `.ct-origin-badge-text` inside it, the
    icon's mask chosen by one of seven `.ct-origin-icon-<kind>` classes on an
    ancestor (sigma, quotation, door, globe, clock-rewind, question,
    hourglass). Those seven masks plus `.value-history-button::before` and
    `.custom-noir-icon::before` are the nine `url()`s that published as 404s
    and now resolve. The RULES are correct — a rendered probe drove all nine
    with injected markup — and NONE of the selectors is emitted anywhere.
    WHAT WOULD HAVE TO EXIST, stated precisely because the previous answer was
    wrong. It is NOT a missing classifier. The Embed SDK this repository
    already compiles against exports `iconClassForTerminator`
    (`viewmodel/viewmodels/origin_chain_types.nim`), a total mapping from
    `TerminatorKindWire` onto exactly these seven class spellings, and
    `client/hydrate/live_origin.classifiedOriginOf` ALREADY READS
    `summary.terminatorKind` — and then discards it, keeping only
    `terminatorExpr`. So the data and the seven-way mapping are both in hand.
    What is missing is MARKUP: `SessionValue.origin` is a single string
    (`debugger/session_view.nim`), and `components/debugger.nim` renders it as
    a `.storigin` button whose `title` is the expression. Emitting the badge
    means carrying the kind through `session_project.stateFor` into
    `StateValue`, and rendering upstream's three-element shape instead of one
    button — a renderer change with a visual-design decision in it, not a
    classifier to invent. It would be visible on the hydrated route only, and
    on the two of ten published captures whose recordings publish source;
    `session_project.nim` says why the other eight cannot ever show it.
    THE NINE SVGs UNDER `client/src/assets/ct-icons/` ARE THEREFORE REACHED BY
    NOTHING TODAY, and they are kept rather than removed, deliberately: the
    rules that name them are upstream's bytes, `ct_styl.rewriteUrls` is total
    over them by construction, and dropping the rules to delete the files
    would have to be undone by whoever wires the markup. What must not happen
    is a comment claiming they are visible to visitors; the icon table in
    `ct_components_css.nim` says this instead.

INERT class separate-bar
    DEFECT 3. A vertical rule between toolbar groups, in
    `shared_widgets.styl`, and its only visible declaration is a left border.
    Nothing emits it, AND MARKUP ALONE WOULD NOT BE ENOUGH: the border binds
    to the subtle-border role and the panel binds to the sunken-surface role,
    and in the DARK theme — which is this register's default — those two roles

    two roles are one rung apart at the pinned commit and this product's ramp
    puts them on the same rung. The values are not quoted here on purpose —
    `tools/design/check-tokens.mjs` and `test_static_export`'s shipped-rules
    scan both reject a raw colour in this layer, and a reason is not worth
    weakening either gate for.

    The bare `class expanded` row that stood here is GONE rather than kept,
    and its absence is the evidence: `.expanded` is a Stylus parent block with
    no declarations of its own, so a correct port emits no rule for it. It was
    only ever reachable as wreckage.

    TEN ROWS AND NOT ONE `expanded-*`, which is what this first said: that
    glob also swallows `expanded-call-args`, which has a row of its own, and
    the register requires exactly one row per selector. `*` is the only
    metacharacter, so the rows are anchored on the first DIGIT — nothing
    generated is `expanded-c…`, and together they cover 0 through 100.

    These are the 101 rules `calltrace.styl:665` generates with
    `for i in 0..100`, and it is listed here because of what it REPLACED. The
    loop was not expanded at all: the port emitted one rule selected by
    `.expanded for i in 0..100-{i}` — the loop header flattened into a
    selector, `{i}` unresolved, `margin-left:0.625em * i` inside it. That
    reached production. Two rows of this register, `class 100-` and the
    `class expanded` above, were that wreckage read back as class names, so
    the register was describing the defect as though it were the design.

    The rules are now emitted as upstream emits them, and are INERT for the
    ordinary reason: CodeTracer writes `expanded-<n>` as an element ID keyed
    on a source line (`renderer.nim:607`), not as a depth class, so no
    `.expanded-N` CLASS is written by the views this page mounts. Correcting
    the port therefore changed what the stylesheet SAYS and not what the page
    looks like — worth stating plainly, because a reader could otherwise read
    the fix as a visual one.
