## What continuity means here

A desktop CodeTracer user must **recognise the tool**: the same pane
vocabulary, the same column semantics, the same ordering conventions, the same
control positions, a comparable density. It does **not** mean pixel identity,
and it does not mean copying affordances that need a running engine or
JavaScript — this route ships **zero JavaScript** by construction, and that
constraint is upstream of every row marked DELIBERATE below.

The distinction that matters when reading the table: a divergence forced by the
no-JS constraint is a *cost of the medium*, and a divergence that is not is a
*defect*. The check's job is to separate them, because the second kind is
invisible without the comparison — it looks like a design choice.

## What already matched

**Superseded 2026-08-29 (round 5).** This section used to read:

> `defaultReplayLayout()` is **consumed, not restated**. The web walks the
> desktop's own `LayoutNode` tree, so pane placement, the weight proportions and
> the State/Event-Log stacking are identical by construction rather than by
> agreement, and a change upstream arrives without an edit here.

The first clause is no longer true and the second was never as strong as it
sounded. `client/src/debugger/session_layout.blockTracerReplayLayout()` now
composes BlockTracer's own tree, so placement is an agreement again rather than
a consequence. What is still consumed by construction is the **model**:
`client/src/debugger/layout_model.nim` is a byte-verbatim vendored copy guarded
by `ci/test/layout-model-vendor.sh`, so `PaneKind`, its wire spellings,
`LayoutNodeKind`, `weight`, `activeIndex` and `validate` cannot drift, and
`components/debugger.paneBody` is total over the enum — a pane added upstream is
a compile error here rather than a blank region. The primitives are the
desktop's; the composition is ours, which is what
`CodeTracer-Embed-SDK.md` §3.2 row 1 puts on the consumer's side of the line.

The "identical by construction" claim was also weaker than it read even when it
was true, because `defaultReplayLayout()` is **not the arrangement the desktop
runs** (row 36). Inheriting it inherited a model of the desktop, not the desktop.

What still matches by direct comparison, and was re-verified this round:

* the source pane's density — 23 px pitch against Monaco's ~24 px;
* the **pane-title register**: both render pane names as short uppercase labels
  (`.panetitle` / `.stacktab` carry `text-transform:uppercase`,
  `debugger_css.nim:144,168`; the desktop's `convertTabTitle`,
  `ui/layout.nim:100-116`, uppercases the `Content` enum name);
* **stack chrome** — tabs replace the pane's own header (row 32);
* **the four panes' screen positions and the left/right split** (row 31);
* **where the stepping controls live** (row 23), which this round establishes
  matches the running desktop and did *not* match it before.

## Divergence table

Verdicts: **CONTINUOUS** — the desktop's treatment, reached by this medium's
means. **DELIBERATE** — a divergence, forced by the medium or chosen for a
reason, and stated. **FIXED** — a real gap, closed in VD.5. **DEFECT** — a real
gap, not closed, with the change named. **OPEN** — a real gap in the evidence
rather than the code. **HUMAN** — needs a call this milestone cannot make.

`CONTINUOUS` and `DEFECT` were added in round 5; the columns are unchanged. In
the brief's vocabulary, `DELIBERATE` is *deliberate divergence*, `DEFECT` and
`OPEN` are *defect*, and `HUMAN` is *needs a human call*. `FIXED` is a defect
that was already acted on and is kept so the reason survives the fix.

### Round 5 — what the rearrangement did to continuity

The short answer is that it **improved** it, and that the check nearly missed
why. Every earlier round in this document compared against
`headless_app/layout_model.defaultReplayLayout()`, because that is the module
this repository vendors. This round read the running desktop as well, and the
two do not agree (row 36). Three consequences:

* **The controls did not diverge by moving — they diverged by being a pane.**
  The desktop mounts its stepping toolbar into `#menu`, the fixed caption strip
  above GoldenLayout's root; `paneDebugControls` is registered with no
  GoldenLayout component and appears nowhere in the shipped layout config. Row
  23 is therefore `CONTINUOUS`, and the arrangement this round replaced was the
  divergent one. The rationale written in `pages/debug.nim` argues the move from
  competitive research and the research does support it — including a P1 row
  asking for exactly this change — but it never notices that it is also what the
  desktop does, which is the stronger argument it had available.
* **Three of the four panes did not move**, and the left/right split is 3:2 in
  both (row 31). The Event Log changed which tab strip it lives behind (row 29),
  which is one thing to relearn, and the desktop's own two defaults disagree
  about that grouping anyway.
* **Two panes were renamed and one of the two is invisible to a desktop user.**
  `Editor` is a headless-model string; the running app labels those tabs with
  filenames, so `Code` diverges from nothing a person sees (row 26). `State` →
  `Values` is a real, noticeable rename with a real reason and a P1 research row
  behind it (row 27). Both kept the desktop's wire spelling, so `#pane-editor`
  and `#pane-state` are unchanged and every machine-addressable name on the
  surface is still CodeTracer's (row 28).

Two things this round did **not** settle. Row 30: the desktop a visitor actually
uses opens the Event Log by default, as a large bottom pane; here it is behind a
tab, and the research's P1 row 5 asks for it to be un-stacked while the same
document's Chrome precedent endorses the tab. That is a product ranking, not a
continuity fact. Row 36: which CodeTracer this document is measuring against —
the exported contract or the shipped experience — has been answered
inconsistently, and B9 is written about a person.

The one **DEFECT** is row 33 and it is latent: the tab-marking CSS is correct for
exactly two tabs with the first active, which is what the shipped layout has, but
`renderStack` is total over a model that carries N-way stacks and any
`activeIndex`, and the desktop's own default ships a three-tab stack. The fix is
the one already applied to the source tabs in row 8.

Syntax highlighting (row 19) closed in the previous pass, and it is
worth saying how, because the blocker as recorded was correct and the fix did
not remove it. The route still refuses a per-language lexer as a *dependency*
— no Monaco, no Shiki, no tree-sitter, no JavaScript. What changed is where the
lexing happens: at static-export time, in Nim, so the tokens are computed once
and shipped as markup. That is available to this route and to no other kind of
front-end, which is the one respect in which the static constraint helped
rather than cost. What it does not buy is breadth: one language is genuinely
supported, and the honest scope is recorded in the row rather than implied by a
profile type that could hold more.

The gaps that mattered most were **not** the ones the no-JS constraint forced.
Rows 1–3 in particular were invisible on any single screenshot: a numeric class
leaking a larger size into dense rows, and two indentation ladders built on a
geometric scale that stopped ranking at the depths the panes are for. Nothing in
the register's own review rounds could have named them, because the rendered
page looked *deliberate*. They were found by comparing against the tool this
register exists to be continuous with, which is the argument for doing this
check at all.

Round 5 adds a second argument for it, and a caution. The argument: a continuity
check is the only review that can tell you a change you made for one reason was
*also* right for another — row 23 moved the controls to satisfy competitive
research and landed on the desktop's own arrangement, and nobody involved knew
that until this check read `index.html`. The caution: for four rounds this
document compared against a Nim module rather than against the application, and
it was confident throughout. Rows 20, 22 and *What already matched* were wrong,
and each of them read as a settled fact. **What could not be determined here** is
which of the desktop's two defaults is the reference (row 36); that is a
CodeTracer decision, and until it is made, a row in this table is only as true as
the file it was read from — which is why every row added this round names one.
